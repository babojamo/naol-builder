# Suit Element Resistance / Defense audit — 2026-10-13

1. **Root cause:** Character-sheet element stats read ability modifiers only; the suit's signed strong/weak resistance was missing. The UI also exposed the raw combat fraction without separating the unverified Character-window display. Observed `Fire Defense` was incorrectly aliased to `fireResistance`.
2. **Current API:** [Official upgrade rows](https://api.flyff.com/upgradelevelbonus), fetched during this audit, report `elementDefense: 6.42` at +7. The app retains fraction 0.0642 and presents the combat value as 6.42%.
3. **Fire +7:** Virashon Suit from the current bundled catalog produces Fire 0%, Water −14%, Wind +14%, Electricity 0%, Earth 0% with no additional resistance sources. Production logic contains no Virashon special case.
4. **Wind:** +14 percentage points; its source breakdown identifies Virashon Suit, Fire +7. With All Elements Defense +10 the result is +24%.
5. **Water:** −14 percentage points, preserved without clamping. With Water Defense ability +5 the result is −9%; with All Elements Defense +10 it is −4%. Opponent builds receive −0.14 and +0.14 fractions as appropriate.
6. **Character-window investigation:** The [official October 23, 2025 patch note](https://universe.flyff.com/news/minorfixesoct232025) confirms distinct resistance/defense displays. The current API provides the combat upgrade value. [Flyffulator entity logic](https://github.com/Frostiae/Flyffulator/blob/89116244b670930ac8633a99212b7f9727bb8c12/src/flyff/flyffentity.js#L1524) confirms ±2 × upgrade resistance. The reference's damage calculator uses the separate upgrade coefficient; inspected evidence does not establish the Character-window transformation.
7. **Exact 5% formula:** NOT verified. The brief's reported Fire +7 → 5% observation is retained as calibration evidence in `tests/fixtures/suit-element-calibration.json`, not a formula constant. `calculateDisplayedElementDefense` returns null/unsupported. UI: “Unavailable / Calibration required.” No claim of independent screenshot verification is made.
8. **Combat behavior:** `elementFactors` retains its existing coefficient algorithm, now using a shared relationship registry. Neither the coefficient nor the sheet suit adjustment is inserted into Ability[]. The opponent boundary transfers sheet resistance once. Skills continue to omit the auto coefficient stage but now respond to the suit's resistance; this corrects the prior test's assumption that suit upgrades never affect skills.
9. **Files:** New `lib/elements.ts`; updated `lib/element-stats.ts`, `combat/formulas/elements.ts`, `combat/character.ts`, `components/CharacterDetails.tsx`, `lib/observed-stats.ts`, `tests/element-stats.test.ts`, `FORMULAS.md`; new calibration fixture and this report. No database migration or Edge Function deployment is needed.
10. **Tests:** Nine additional regressions cover all five +7 relationships, absent/none/+0 suits, current Virashon sheet and rendered UI, individual/all-element stacking, negatives, source attribution, opponent fractions, coefficient independence and unresolved display calibration. Existing skill/UI/observed tests were updated to the corrected semantics.
